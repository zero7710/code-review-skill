# 审查与复查一次改动

## 确定要审的版本

记录改动意图、任务来源、基准、待审版本、适用的仓库规则及实际可用的验证材料。审真实 PR 时读取目标分支、当前 head、已有意见及其原讨论。全量 PR 差异从目标与 head 的共同祖先算起。若 PR 修改审查规则，以已采用版本为准，同时审查提议中的规则变更。用户要审未提交改动时，涵盖所选范围的暂存、未暂存和新增文件，注明工作区快照，留意工作区在审查期间是否变化。首次基线针对指定版本与范围登记存量问题，手动复查绑定指定版本及已有记录，两者单独标记来源。盲测时只使用评测方提供的当时材料。

开发 Agent 创建 PR 前，依据改动意图运行可直接验证行为的检查，保留命令、实际结果及必要截图，再交给独立子 Agent 预审。已有 PR 或只读审查请求则直接读取可用证据。收到修复任务后才修改代码，收到发布或处置 PR 讨论的授权后才执行相应外部操作。

## 分派与复核

按下表分派只读任务。发现方与复核方使用独立新上下文，例如在支持的工具中使用 `fork_turns="none"`。给每位成员仓库位置、任务意图、适用规则、实际差异和范围，将上游代码、测试及调用方作为自行查证的材料。作者判断、其他 Agent 的判词和历史盲测答案不作为发现方的输入。成员只回传证据和结论，由主 Agent 统一发布或交接。

| 角色 | 给该角色的任务 |
| --- | --- |
| 并行发现 | 分派给不同子 Agent，一位从业务入口追踪预期行为与数据变化，另一位从调用方、已有数据及受影响路径检查回归。修复类 PR 要查原先出错的根因。每个候选给出可达的触发条件、错误后果、对应提交的文件行号与已查证的依据。查完允许返回零条。 |
| 独立安全审查 | 单独检查本次改动触及的身份、授权、数据范围和敏感信息处理等信任边界。以源码和适当的隔离检查说明风险、受影响行为与修复方向，记录该审查的实际覆盖情况。 |
| 独立复核 | 换一组未参与发现的子 Agent。逐条交付候选主张与代码位置，各自先找反证，例如上游拒绝、下游约束、事务边界或有意保留的兼容逻辑。独立记录支持、反对或证据不足及理由。能直接验证时附实际检查结果。对照基准判断缺陷来源。 |

按仓库已校准的复核口径汇总票与依据。没有数值门槛时，要求有独立支持、证据链完整且关键反证已解决，再列为已核实。若环境缺少独立执行能力或某一路失败，标记本次审查不完整，写出实际完成的检查与缺口，保留未经独立复核的候选。

正式摘要以已核实的问题数开头，按影响排序。每项写清触发条件、错误后果、可定位的代码证据、根因及本轮已核实的同类位置。重要性取 Important 或 Nit，确认历史问题时另标 Pre-existing。能附到 PR 差异的意见指向相应代码行。过滤纯样式、机械清理和泛泛的测试建议。零条时说明覆盖范围和仍待验证的部分。保留候选被否决或合并的简要依据，与正式意见和独立安全审查结果分别交付。

## 复查及结束条件

- **计轮。** 针对一个 PR 版本，完成分派、复核和一次汇总才算一轮。并发子任务和未形成结论前的失败重试都沿用当前轮。复查沿用运行记录里的意见编号、原讨论、上次完成审查的版本和未决验证条件。
- **范围。** 第 1、2 轮可查完整 PR 及其受影响路径。第 3 轮以“上次完成审查的提交 → 本轮提交”的两点差异为新增范围，同时逐项验证未决意见。可读取相关上下文。指定第三轮却缺少上一轮版本或未决索引时，先从可用记录恢复，仍有缺口就说明受限范围和所需材料。
- **处置。** 同一根因在本轮一次列出已核实的所有位置，修复方检查本次改动的同类实例。在原记录追加修复提交、验证证据或附理由关闭的决定。每条旧意见的本轮结果取“仍可触发”“已验证修复”“附理由关闭”或“本轮未验证”。未覆盖或本轮没再报告的旧意见保留原处理状态。已验证修复后确实再现，关联两次证据并标记复发。
- **停止。** 有新发现或旧意见仍开放时，列出待修复事项及下一位处理人，等待新版本或处置决定。任一轮没有新发现、已发布意见均已验证修复或附理由关闭，可结束 AI 审查。第 3 轮仍未解决则暂停自动审查与修复，向负责人交接证据、已尝试的修复和需要决定的事项。

## 报告人工与仓库门禁

依据改动的触发条件和影响评估风险。向目标项目核对哪些路径要求负责人审查、需要几位人类批准、谁可以计入人数，以及已有批准是否仍适用于当前提交。报告适用的规则、实际审批人及其覆盖的提交。AI 复核票用于判断候选意见是否成立。规则、身份或批准范围缺失时，写明待确认的具体事项。

分别报告本轮 AI 审查结论、当前提交的 CI、人工决定和平台实际门禁。列出仍开放的正式缺陷与安全意见，依据项目规则说明哪些意见会阻止合并，以及由谁发起合并。平台状态以实际回执为准，缺少回执时标为待同步。交接时附验证方式、风险和适用的回退方法。有合并队列或发布证据时，记录在最新主分支上的复验和发布后的观察结果。
