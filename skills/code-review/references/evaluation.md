# 用历史 PR 评测审查器

当用户要跑基准、比较提示词／工具／模型、判定正常样本中的审查噪声时读取本页。日常 PR 的发布与复查走审查入口。这里的一轮是对冻结样本的一次独立盲审。

## 准备两个隔离的数据包

| 数据包 | 包含内容 | 可见角色 |
| --- | --- | --- |
| 审查输入 | 当时的 PR 说明、基准与待审提交、差异、当时可读的仓库规则和验证材料 | 本轮审查及其独立复核子 Agent |
| 判分材料 | 事故、后来修复、人工确认的触发条件／错误后果／代码依据、预先标记的关键缺陷、正常样本的确认理由、判分样例 | 评分 Agent 和裁定者 |

只把审查输入发给新上下文的审查 Agent。盲审时用隔离的历史快照，提供当时版本的必要依赖。避免通过当前分支、后续 Git 历史、PR 后来的讨论、测试、文件名或工具访问泄露答案。向评分者保留审查输出和证据的位置，可用稳定 ID 关联。涉及数据不足、工具失败或缺少正常样本确认理由，先记录待补材料，勿把未运行计作未命中。

## 执行和判分

1. **入集。** 事故须经熟悉该模块的人确认，能还原引入问题的 PR，并能指出当时已可见的证据。其余事故保留在事故记录中。正常样本也须由人确认当时预期有零条值得处理的意见，记录理由。按原始 PR 划分调优集和保留集，同一 PR 的多个缺陷始终同组。
2. **盲审。** 调优与每日重跑使用调优集。版本验收时在同一保留集上固定评分器、口径和标定样例，新旧版本各自独立跑 3 轮。每轮对每个 PR 执行一次完整审查，然后逐个缺陷对照正式输出。保留全部轮次，不从多个结果挑选最好的一轮。
3. **判命中。** 人先标定少量样例。独立评分 Agent 核对触发条件、错误后果和可靠代码依据，三项匹配才命中。证明同一行为的调用点也有效。一个缺陷每轮最多记一次，争议由人裁定并保存原因。评分口径变化时，对新旧输出重新判分。
4. **判噪声。** 真实 PR 中被采纳的正式意见先计有效，有反证可改判。判断错误、行为符合预期、影响太小分别计为无效，未回应记待定。正常 PR 的每条无效意见都计数，照做会损害正确行为另标有害。若人工核实正常样本含真实缺陷，从新旧两版的正常名单同时移出该 PR，更新样本集版本并重算。零评论 PR 留在正常分母里。
5. **交付。** 日常比较时保留样本及其运行、评分来源，报告具体进步、退步和噪声变化。验收时选出每个版本看见和漏掉的关键案例、依据与原意见。关键缺陷命中次数下降，或出现旧版没有的有害建议，都须人工复核。由人决定是否采用新版并记录理由。

## 本地计分

在 Skill 目录运行。脚本使用 Python 3 标准库，从已经判定的记录计算指标，向标准输出写 JSON。它不执行审查，也不访问模型、仓库服务或管理后台。

```shell
python scripts/score_eval.py baseline.json
python scripts/score_eval.py baseline.json candidate.json
```

下例是虚构的**评分侧汇总输入**。每个版本各提供一个 UTF-8 JSON 文件，仅向评分方传递。

```json
{
  "dataset": "example-holdout-v1",
  "grader": "grader-v1/rubric-v1/calibration-v1",
  "split": "holdout",
  "rounds": 3,
  "reviewer": "reviewer-baseline-v1",
  "defects": {
    "D1": {"pr": "example#12@abc123", "critical": true, "hits": [true, false, true]},
    "D2": {"pr": "example#12@abc123", "critical": false, "hits": [false, true, false]}
  },
  "clean_prs": {
    "example#20@def987": {},
    "example#21@abc321": {"remove-compatibility-check": "harmful"}
  },
  "real_feedback": {
    "example#25/thread-1": "accepted",
    "example#25/thread-2": "intentional",
    "example#28/thread-1": "pending"
  }
}
```

- `dataset` 标识同一冻结样本及正常样本名单。`grader` 同时标识评分器、判分口径和人工标定样例版本。`reviewer` 标识本次具体的提示词、工具与模型组合。`split` 可取 `tuning` 或 `holdout`。后者验收时固定 3 轮。
- `defects` 的键是稳定缺陷编号。`pr` 标识仓库、PR 和当时版本。同一 PR 可有多个缺陷。布尔数组按实际轮次记录最终判分，一个值对应一次已完成的审查。出现争议先裁定，并将依据另存于对应判分记录。
- `clean_prs` 为该版本在同一批正常 PR 上的逐 PR 盲审结果，每份汇总每个 PR 取一次预定运行。零意见用空对象。有意见时用可追溯的稳定建议编号区分独立意见。跨版本若是同一 PR 对应的同一建议，两版沿用编号，使改写措辞不被当作新增有害。取值为 `invalid` 或 `harmful`，两者都进入无效意见数。
- `real_feedback` 按该审查器版本实际发布的评论编号列出当前判定。可选 `accepted`、`wrong`、`intentional`、`low_value`、`pending`。改判时以最新状态重算，同一评论只进入一次统计，另保留理由与历史。实际流量可能不同，比较时同时给出各自分母、范围和待定数。

输出的 `round_recall` 给出每轮检出率，`pooled_recall` 汇总所有缺陷与轮次，`defect_comparison` 保留两版每个缺陷的逐轮布尔值和命中数差。真实 PR 的 `real_invalid_rate` 分母为有效加无效。正常样本的 `clean_invalid_per_pr` 分母为全部正常 PR 个数。比例输出分子、分母和小数值，空分母用 `null` 表示。空对象可用于明确某一路没有样本，不解释为质量已经验证。

两版比较时，脚本核对数据集、评分器、集合用途、轮数、缺陷清单／关键标记、PR 快照和正常样本名单。输入不完整或口径不匹配时返回非零状态。成功计分后，`manual_review_triggers` 列出关键退步和新有害建议，应连同对应原文与证据交给裁定者。此列表为空也不会产生自动升级决定。
